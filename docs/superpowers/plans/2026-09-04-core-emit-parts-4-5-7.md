# Phase 3b: emitters for IDTA 02035-4, -5 and -7 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `@passwerk/core` emits Technical Data (part 4), Product Condition (part 5) and Circularity (part 7) from `PassportDraft`, the golden samples stay `valid`, a new broken sample proves L3 catches a missing mandatory element, and the oracle set grows to 14/14.

**Architecture:** Three new emitters under `src/emit/submodels/`, each built only through the catalogue-path builders in `elements.ts` and the header copier in `shared.ts`, wired into `buildEnvironment` in part order. `Field` gains `recordedAt` for part 5 timestamps. Five new composite shapes. Fail-honest everywhere: missing mandatory leaves are reported by L3, never papered over.

**Tech Stack:** TypeScript 5.9 strict ESM, Zod 4.5.4, decimal.js 10.6.0, aas-core3.0-typescript 1.0.5, Vitest 4, Biome 2, pnpm 10.

**Spec:** `docs/superpowers/specs/2026-09-04-core-emit-parts-4-5-7-design.md` (the mapping tables in sections 4 to 6 are normative; this plan does not repeat them).

## Global Constraints

- No `node:*` imports under `packages/core/src` (ADR D-006).
- No semanticId, idShort or legal reference typed by hand; every element goes through `property`, `multiLanguageProperty`, `collection`, `list`, `file` with a catalogue path.
- Numbers stay decimal strings; `integral()` is the only normalisation and only for `xs:integer`/`xs:unsignedInt` targets.
- Dates are ISO-8601 strings; `recordedAt` and `createdAt` are the only timestamp sources.
- Emitters tolerate drafts that failed L1 (loose input interfaces, `Partial<>`), never throw on missing members.
- Instances never set `idShort` on direct children of a `SubmodelElementList` (the builders handle it).
- Every new finding message would need DE and EN; this slice adds no new rule ids.
